# Interview rules

## What to ask

- Only decisions with a real choice: product behaviour, audience, trade-offs, ownership, naming the user cares about.
- Highest-impact first: questions that change the data model, access, or the split come before cosmetic ones.

## How to ask

- Use the question tool when one is available, with the recommended option first.
- Each question stands on its own: name the ticket and the thing it decides. The user may see only the question dialog.
- Give each option a one-line consequence, not just a label.

## When the user doesn't understand

- Don't repeat the question. Stop and ask what's unclear if they haven't said.
- Re-explain with a concrete scenario: who does what, what happens today, what goes wrong without a decision. Show a small example of the data or flow.
- Then re-ask in the new terms, offering a short reply format (e.g. "1A, 2B").

## Recording answers

- Apply each answer to every affected ticket right away, under "Decisions" or in Scope.
- When an answer differs from the recommendation, follow it; mention a consequence once only if it's material.
- If an answer creates a new question, ask it in the next batch rather than assuming.
